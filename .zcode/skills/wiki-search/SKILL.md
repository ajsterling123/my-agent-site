# Wiki Search —— 基于资料的 Wiki 问答（RAG）

本站（实验档案）Step 9 的自定义 Skill：把「问我的 Wiki」变成一次
**离线检索 + 只按检索结果回答** 的对照流程。检索逻辑全部在
`scripts/search_wiki.py`（离线、只读、确定性、纯标准库、不写任何文件），
本技能负责跑检索、按协议回答、守住「证据边界」。

## 何时使用

- 用户问到**自己的笔记、概念理解、项目决策、以往记录**——凡是「我以前
  怎么想/怎么做/记过什么」这类问题；
- 用户要求在 Wiki 里**查找 / 检索**某个知识点；
- 课程验收要求实际执行一遍本工作流（含「Wiki 里没有」的对照问题）。

## 回答协议（逐字遵守）

```
你是我的个人 Wiki 助手。只能依据 SOURCES 回答。
每个关键结论后标注 [SOURCE n]，n 对应检索脚本输出的序号，并在来源处写明文件名。
资料不足时回答「当前 Wiki 中没有足够依据」，不要利用一般知识冒充我的记录。

QUESTION: <问题>
SOURCES: 运行 python scripts/search_wiki.py "<问题的关键词>" 的输出
```

## 工作流

1. 从用户问题里提取关键词，运行检索脚本取得 SOURCES（Windows 下用
   `python`，不要用 `python3`；脚本只读，不写任何文件）：

   ```bash
   python scripts/search_wiki.py "<问题的关键词>"
   ```

   命中太少时换关键词重试，或加 `--include-rules` 把规则文件也纳入检索；
   机器可读输出用 `--json`。
2. **只依据 SOURCES 回答**：引用片段逐字摘录，不 paraphrase 成新结论；
   每个关键结论后标注 `[SOURCE n]`（n = 检索输出的序号），并在来源处写明
   文件名（如 `agent-experiment.md`）。
3. SOURCES 为空或不足以支撑结论时，直接回复**「当前 Wiki 中没有足够依据」**：
   禁止用一般知识兜底，禁止把百科知识写成「我的记录」。
4. Wiki 里没有的内容，即使你知道答案，也只能说**「Wiki 里没有这条记录」**，
   并可以另外注明「以下是一般知识，不是你的记录」——两种话必须分清，
   不得混在一段里让用户分不清哪句来自他的 Wiki。

## 纪律

- 检索脚本是只读的：不要为了「让问题有答案」而往 `content/wiki/` 塞新词条；
  Wiki 没有记录就如实说没有。
- SOURCES 的序号以本次检索输出的序号为准，换一次检索就重新对应一次。
- 回答里的引文必须是 SOURCES 原文片段（逐字），改写、缩写、加推论都不算引用。
