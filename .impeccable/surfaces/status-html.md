# Surface Brief: 状态登记表

**用户是谁、来干什么**：任课老师/助教按验收清单核对站点时，要一眼看到「这个站现在有多少页、多少内容、数据文件是否对得上账」。状态页是档案的台账页，不是仪表盘——不画图、不加卡片，用首页「身份登记」那同一本 dl 账本回答问题。

**primary_target**：`public/status/index.html`（由 `scripts/build_status.py` 生成，不手改输出；改站点请改内容源后重新构建）。

## 已实现的形态

- 骨架照全站先例从 `public/index.html` 外科改写：报头带（3px 双线 → 元信息行 → 导航行 → 1px 实线）逐字节同构，导航 aria-current 落「状态」（菜单第 7 项），页名用 `.folio` 档，页脚说明句按页改写，STEP 10/12。
- `.folio` 之下一句 `.intro` 说明账目口径与 ✓/✗ 含义，然后三个 `.sec` 栏目（栏目题压 1px 实线，与全站同档）：
  1. **站点登记**：页面总数 / 最近更新；
  2. **内容登记**：文章 / Wiki 词条 / 论文 / RSS 订阅源 / RSS 聚合条目；
  3. **数据健康**：论文数据 / 订阅聚合 / 订阅源 feed / Wiki 生成页，每项一行 ✓/✗ 与差异详情。
- 机读数据用等宽档：计数与时间戳包 `.register .num`（Consolas 15.5px / 0.04em / tabular-nums，与登记邮箱同一副字体规格），单位（页/篇/条/个）留在等宽段之外。
- ✓/✗ 是普通文字、沿用正文墨蓝：**不上红**——对不上账是事实陈述，不是「活动」，红色纪律不为此开例外。
- **零 JavaScript**：所有数字构建期烤进页面；「最近更新」= 内容源 frontmatter 日期最大值（内容派生、跨提交稳定，可对账）；**不写「当前时间」，也不登记「最近构建」**——构建时刻的归宿是每次运行的 run_id 日志（run_id 前半即 UTC 时间戳），页面只展示内容真相：一个文件写不下包含它自己的那次提交的时刻。同一份仓库状态重复构建字节一致。
- 本页唯一的新 CSS 是 `.register .num` 一条规则，其余全部复用既有词汇。

## 纪律（不得违反）

- 不新增颜色、不加卡片/图标、不用红色、零动效——台账页比栏目页更素。
- 页面上的每个数字都必须与 `public/data/status.json` 一致（`tools/check_status.py` 交叉核对）；计数从内容源重算，不手维护。
- 对账不一致时页面如实展示 ✗ 与差异详情，构建不因此失败。
- 生成页带生成标记 `<!-- 由 scripts/build_status.py 生成 -->`，由 `tools/check_site.py` 校验。
