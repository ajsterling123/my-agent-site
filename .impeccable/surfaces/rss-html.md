# Surface brief: public/rss/index.html —— RSS订阅（已实现）

## Scope & visitor mode

整站页面之一，六项导航里插在「博客」之后的那一项。与其它页面不同，本页条目由 `public/rss/reader.js` 读同域 `../data/rss-items.json` 后逐节点渲染（构建期由 `scripts/fetch_feeds.py` 抓取并规范化）。访客模式 **Read**：读者要在几秒内看清「订了哪几个源、每个源最近写了什么」，并点进原文。条目多起来（当前 73 条、六栏）之后，页首补了**目录**与**筛选**：读者先看索引决定读哪一栏，或直接筛出要找的那条。

## Audience, job, action, proof, constraints

- 受众：读者（本人与同学）、以及按 Step 验收的老师/助教——他们要看的是「外部源真的接上了、而且只当文本」。
- 任务：按源浏览最近的条目，点标题去源站读全文；条目多了以后，还要能**先跳到某一栏**或**筛出关键词**。
- 行动点：目录行与「回到目录」是页内跳动、筛选框是输入、条目标题与栏目题下的出处是站外跳转（新窗口）、页尾 OPML 是下载——五个都指向同一件事：少翻页，快找到。
- 证明：页面本身就是证明——6 个源分栏、73 条真实条目（2026-10-08 抓取），每条带源站绝对地址；目录里的日期与条数是从 JSON 算出来的，不是写死在页面里的（`tools/check_feeds.py` 会核对骨架里没有任何源名）；同一个脚本还会核对数据、OPML 与渲染脚本，并跑一次敌意样本负向测试。
- 约束：外部内容只当纯文本（`textContent` 逐节点渲染）；不加卡片、图标、阴影、徽章；外部内容静止态不用红；禁 JS 时不白屏（目录与筛选框也由脚本生成，所以禁 JS 时它们同样不出现，并有一句话说清）；480px 单列、320px 无横向滚动。

## Chosen direction & memorable moment

沿用「实验档案」世界，本页是档案里的**订阅登记册**：页首一份**目录**（按源一行：左列等宽最新日期，右列源名与推到行尾的等宽条数），其下每个源是一栏，栏目题（源标题）压在 1px 墨蓝实线上、题下一行源站地址作**出处**，栏内每一条登记一行——等宽日期、宋体标题（外链）、一句深蓝灰摘要，行间发丝线，栏末一行小字「回到目录」。它不 是「信息流」，也不给外部内容任何特殊待遇：别人的文章和本站文章在同一张账本上、用同一套字与线。
难忘点：**目录、栏目、条目是同一张账本的三个高度**——索引行最紧（六行一屏读完）、栏目题压线、条目行最松，一路读下来像翻一份编了号的卷宗；外部世界再热闹也不许让页面上色。

## Direction contract

THESIS: 订阅不是流，是登记册——日期与条数是机读数据（Consolas + tabular-nums），名字是档案条目（宋体加粗），摘要是次级说明（#5F6E7D）。

OWN-WORLD: 与首页同一个世界。本页复用 `.sec h2`（栏目题压 1px 实线）与博客列表那四个账本类（`.post-list` / `.post-row` / `.post-date` / `.post-item`）；目录复用同一张账本，只把行距收一档、把条数推到行尾。本页自己的 CSS 全收在 `styles.css` 的「RSS订阅」注释块里：`.rss-reader .post-date span`（同日时刻两行）、`.rss-toc` 一族（索引行距与行尾条数）、锚点落点 `scroll-margin-top`、`.rss-source`（出处那一行等宽地址）、`.rss-filter` 一族（填空线式的筛选）、`.rss-note` / `.rss-back`（说明与回跳的小字）。零新色、零新字体、零新圆角、零阴影、零动效。

STORY: 访客点「RSS订阅」→ 看到页名与一段说明 → 先读目录：哪个源最近更新、各有多少条 →（要么直接点某一栏跳过去读，要么在筛选框里敲一个关键词）→ 逐条读，点标题去源站原文（新窗口），想知道来源就看栏目题下的出处 → 一栏读完点「回到目录」回索引 → 需要订阅这些源就看页尾的 `subscriptions.opml`。

FIRST VIEWPORT: 报头带（导航当前项「RSS订阅」墨蓝加粗下划线）→ `.folio` 页名「RSS订阅」→ 一段 `.intro` 说明 → 一条填空线式的筛选行 → 「订阅目录」栏目题与其下六行索引（每行：左列等宽最新日期，右列源名，条数推到行尾）。1268×900 实测六行索引一屏读完，第一栏的栏目题落在首屏之内（y≈783）。

FORM: 页面骨架手工写成（与其它五个手写页同构，导航块逐字节一致）；目录、出处、筛选、条目、计数与空状态全部由脚本从同域 JSON 生成；数据与清单由构建脚本生成，不手改。

FINISH: 与整站同批通过 `tools/check_site.py`（本页在 `public/rss/` 下，是唯一允许站外导航链接的页面）与 `tools/check_feeds.py`（含敌意样本负向测试、以及「href 只有一个出口」「骨架不写死源名」两条新断言）；DESIGN.md 已补「订阅阅读器」的目录 / 出处 / 筛选 / 回跳四个部件与 The Index Rule。

## Signature interaction

筛选框：本页唯一的输入动作。敲字即筛（标题 + 摘要，大小写不敏感），没命中的整栏从页面上移除，目录只剩命中项并显示各自的命中条数，另一行小字（`aria-live`）报出「匹配 N 条，来自 M 个源」，一条都没命中时说清「清空筛选框可看全部 N 条」。它是瞬时的，没有动画、没有过渡、没有加载态——重画是同步的，73 条一到两毫秒就位。
其余动作：目录行与「回到目录」的页内跳动（瞬间定位，不带缓动），条目标题与出处的 hover 变红（沿用全局链接响应，瞬时）。全站唯一动效仍是首页的盖章。

## Unresolved decisions

- 退出码与新鲜度：`rss-items.json` 是提交进仓库的生成物，部署工作流按用户明确要求**不改动**，因此线上数据是「最后一次本地抓取」的快照，不是每次部署都重抓。要变成每次部署自动刷新，只需在主部署工作流里加一行 `python3 scripts/fetch_feeds.py`。
- 条目总数会随各源 feed 长度变化（少数派/美团/云风都是 10–20 条）；目录解决的是「先去哪一栏」，所以**仍不分页、不设每栏上限**——一页读完 73 条还可接受，等某一栏自己长到几十条时再谈折叠或分页。
- 同一栏同一天多条的判定是按「源内同一日期出现两次以上」整栏切换到「日期 + 时刻」两行显示，而不是只给冲突的那几条加时刻——同一栏里日期格式不混排比省一行更重要。
- 筛选是「就地筛」而不是「换一张结果列表」：源分栏结构在筛选后保留，因此读者仍知道每条是谁家的。若将来要按时间混合各源（一条时间线），那是另一种页面，不是本页的一个开关。
- 筛选只匹配标题与摘要，不匹配源名；若要「只看 Solidot」这类需求，正确做法是点目录跳过去，而不是把源名塞进关键词匹配。目录里若出现两个同名源（不会发生，config 的 id 唯一），锚点仍由 id 派生。
